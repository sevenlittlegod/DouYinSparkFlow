# 多账号配置网页

这是单服务器上的账号配置入口。管理员可直接编辑和扫码更新账号，也可生成邀请让本人填写；账号配置单独存储，由串行 worker 执行。原 `.env` 账号需要安全迁移后才能在网页管理，不能在旧发送器仍启用时直接重复添加。

## 管理员使用

1. 打开 `/spark/admin`。首次用服务器 `portal-data/admin-token` 的初始化凭据进入绑定页面，设置密码、用验证器 App 扫码，并输入当前动态码确认；保存页面只展示一次的 10 条恢复码。以后使用“密码 + 6 位动态码”登录，初始化凭据不再具有登录或重新绑定权限。
2. 给别人接入时创建邀请，私下发给账号本人。管理自己的账号则直接点击账号卡片的 **编辑 / 重新登录**；管理员密码＋验证器登录保持有效，不必生成邀请。
3. 本人填写并提交后，在账号列表查看待审核版本：本人抖音号、好友昵称与抖音号、消息、执行时间和通知是否配置。
4. 点击“审核并启用”批准当前版本。保存只是提交审核；启用才允许 worker 按所选时间执行。如果今天的时间已过且今天未运行过，会尽快排队执行。
5. 用户后续修改仍需审核。正在执行的配置不会被未审核修改替换。可停用账号，或撤销/重新创建邀请。停用阻止之后的新运行，不能撤回已经发送的消息或即时中断已启动的任务。

所有时间固定为北京时间。每个账号当天最多自动启动一次，失败或进程中断也不会盲目重发；修改配置、服务重启、关闭后重新启用都不会绕过当天记录。旧 `.env` 仍有任务时，网页 worker 在 **08:30–09:10** 保留旧任务优先窗口。旧任务迁移并置空后，网页账号从各自设置时间串行排队，不再统一延迟到 09:10；仍与扫码服务共用浏览器任务锁。

## 账号本人填写

1. 用管理员发来的邀请链接打开专属表单，填写账号备注。邀请凭据进入后会从地址栏清除。
2. 勾选允许服务器读取本人的登录状态和最近会话，点击 **扫码绑定**。等待服务器启动二维码，用本人抖音 App 扫码并在手机确认。建议电脑显示二维码、手机扫码；二维码过期可取消后重新开始。
3. 页面会显示核实后的昵称和本人抖音号，并读取最近会话。已有有效登录时，点击 **读取已保存账号的会话** 即可，不需要再次扫码。
4. 搜索并勾选好友，点击 **应用所选好友**。名单按抖音号区分，同名会话会提示先在抖音设置不同备注。手填和未读取到的好友会保留；仍可在下方按 `昵称 抖音号` 手动增删。最近会话不等于全部好友，读取不完整时页面会明确提示。
5. 填写消息、北京时间和自己的 PushPlus Token，核对后提交。扫码结果只随本次提交进入待审核版本，管理员批准前不会替换当前启用配置。`[API]` 沿用项目的每日一言功能。
6. 后续修改仍可使用原邀请；Cookie 和 Token 不回显，留空保留已有配置。失效时重新扫码，再提交审核。

扫码和读取本身不发送消息。排队及未提交结果从创建起最多保留 15 分钟，浏览器扫码 / 验证窗口最多 12 分钟，页面按实际截止时间倒计时，超时后重新开始；取消、退出当前登录或撤销邀请后不能再使用旧结果。一次只处理一个浏览器任务，08:20–09:10 不启动扫码，避开原定时任务；等待较久时可稍后再试。每个账号 15 分钟内最多启动 5 次，以免小内存服务器过载。

扫码后本人抖音号由服务器的本人资料响应核对。已有配置的账号扫成另一个账号会被拒绝；扫码完成后手动替换抖音号或同时粘贴另一份 Cookie 也会被拒绝。抖音要求额外验证时，页面会显示完整提示及能识别的操作按钮；本人可选择短信验证并直接填写验证码；手机刷脸需扫描平台提供的验证二维码，可点击“放大查看验证页面 / 二维码”。验证码只用于当前账号这次登录，不要发到聊天里。未识别的滑块、人脸或设备验证仍需本人在抖音完成，网页不会自动破解或代过安全挑战。

**手动导入仍可作为备用**：展开“手动导入登录凭据”，填写 sessionid、完整 Cookie 字符串或 Cookie JSON。格式正确不代表会话有效；复制后不要点击抖音网页版“退出登录”。网页扫码使用服务器自己的浏览器，不读取用户电脑上其他浏览器的登录态。

## 首次配置微信通知

PushPlus（推送加）将任务汇总推送到填写者自己的微信。首次可以留空，续火花仍正常运行；已经配置过时留空会保留原 Token，关闭通知需要明确勾选对应选项。

打开 [PushPlus 一对一消息页面](https://www.pushplus.plus/push1.html)，按官网提示登录并关注官方服务号。平台当前要求实名认证后才能使用发送接口，相关费用见 [官方实名认证说明](https://www.pushplus.plus/doc/function/verify.html)，身份信息不填写到续火花页面。在官网创建独立的“消息 Token”（可命名为“抖音续火花”）并复制回填；已有用户 Token 也可用。[两种 Token 的官方说明](https://www.pushplus.plus/doc/help/token.html)。

可先在官网“试一试”给自己发消息，微信收到后再保存配置；未收到时按 [官方排查说明](https://www.pushplus.plus/doc/help/message.html)检查关注、实名和接收设置。Token 用于向自己的微信发送通知，请勿公开分享。

## 运行与数据位置

| 路径或服务 | 用途 |
| --- | --- |
| `/opt/douyinsparkflow` | 项目代码和部署文件 |
| `config/.env`、`logs/` | 原账号的私有配置与日志 |
| `portal-data/portal.sqlite3` | 邀请、会话、待审核及启用版本，含登录凭据 |
| `portal-data/admin-token` | 首次绑定或 SSH 恢复后的初始化凭据 |
| `account-data/runs.sqlite3` | 账号/日期幂等记录 |
| `account-data/<账号内部ID>/<日期>/` | 当次私有 `.env`、`last-run.json` 和 `runtime.log` |
| `douyin-portal.service` | 仅监听本机 18766 的网页服务 |
| `douyin-account-worker` | 网页账号串行任务容器 |
| `douyin-binding-worker` | 独立扫码及最近会话读取容器，无公开端口 |
| `douyin-spark-flow` | 原账号定时容器 |

这些私有目录已加入 Git 和 Docker build 忽略。SQLite 和运行配置使用受限文件权限；这是访问权限保护，**不是数据库加密**。备份时应保护这三个私有目录；不要把数据库或环境文件放入公开仓库。

## 部署与维护

网页服务器使用 Python 标准库和 `portal/requirements.txt` 中的 qrcode（本地生成管理员验证器二维码）；抖音二维码来自服务器浏览器中的官方登录页。worker 使用项目既有 Playwright 镜像。先创建 `.portal-venv` 并安装该依赖，参考 `docker/portal.service.example` 调整运行用户和域名。为网页配置 HTTPS 反向代理（例如 nginx `/spark/` 转发 `http://127.0.0.1:18766/`），设置 `PORTAL_PUBLIC_ORIGIN=https://你的域名`、`PORTAL_BASE_PATH=/spark`，代理保留 Host。不要将 18766 直接开放公网。

网页服务与 worker 必须使用同一系统 UID/GID，保证 SQLite 回滚日志也能互相恢复。Compose 默认 `1000:1000`，其他机器用 `PORTAL_UID` / `PORTAL_GID` 调整。将 `portal-data/`、`account-data/` 和既有 `logs/task.lock` 的属主设为该用户（目录 700、锁文件 600）；原 root cron 仍可使用同一锁。原配置 `config/.env` 需对该用户可读；worker 只读挂载它，用于阻止原账号重复接入。

```bash
cd /opt/douyinsparkflow
docker compose -f docker-compose.portal.yml up -d --build
sudo systemctl status douyin-portal
docker logs --tail 30 douyin-account-worker
docker logs --tail 30 douyin-binding-worker
```

首次初始化凭据可在自己的 SSH 终端查看（不要将输出贴回聊天或日志）：

```bash
ssh hz_ali 'cat /opt/douyinsparkflow/portal-data/admin-token'
```

动态码每 30 秒更新，允许前后一个时间步的时钟偏差，并拒绝重复使用已经验证过的时间步。密码保存为随机盐 + PBKDF2-HMAC-SHA256（600,000 次），恢复码只保存摘要；TOTP 共享密钥由服务器保留，受数据库文件权限保护。绑定确认前不启用 MFA；升级时旧的单凭据管理员会话失效，账号本人填写会话保留。连续失败会限流，重启不会清除限流记录。

手机暂时不可用时，登录页勾选“改用一次性恢复码”，输入密码和一条未使用的恢复码。如果忘记密码，或丢失验证器并需要重新绑定，由服务器管理员在 SSH 内执行：

```bash
sudo systemctl stop douyin-portal
cd /opt/douyinsparkflow
.portal-venv/bin/python -m portal.auth --data-dir /opt/douyinsparkflow/portal-data --reset-admin
sudo systemctl start douyin-portal
```

该命令作废原密码、验证器、恢复码和管理员会话，并生成新的初始化凭据；账号配置和任务不会删除。重新打开管理页完成绑定。没有公开网页“关闭 MFA”或“忘记密码直接重置”入口。密码和手机绑定需管理员本人操作，无需发送给维护者。

如已核对失败记录，需要手动执行当天尚未尝试的目标：

```bash
docker exec douyin-account-worker python -m account_worker --resume-account <账号内部ID>
```

补跑要求当天且已审核版本一致；已提交、提交结果不明、存在草稿或输入失败的目标不会被自动重复发送。完整成功任务不接受再次补跑。首次手动运行可用 `--run-account <账号内部ID>`，同样遵守每日幂等与旧任务保护时段。请先核对名单和登录身份，再手动执行。

正常结束时，每个账号只使用自己的 PushPlus Token 发送结果汇总。新版发送流程要求出现与本次内容一致的新发出消息、输入框清空且短暂等待后无失败提示，才记录已提交；缺少证据则标记结果未知并停止，不自动重发。已提交仍不等同于送达/已读；早期历史记录仅依据发送按键，不能当作实际发送证明。停机、进程被强制终止或网络中断时不能保证推送送达。

小内存服务器的 worker Compose 使用只读源码挂载；更新源码会影响下一次任务，请在没有任务执行时完整更新对应目录。依赖变化仍需重新构建镜像，不能仅更新源码。原账号的独立 cron 容器不受这些挂载影响。

## 扫码服务维护

`portal.binding_worker` 使用 Playwright 镜像内的无界面 Chromium；与发送器共用 `logs/task.lock`，按账号/登录会话隔离数据库中的临时任务。它只打开登录及会话列表，不进入聊天输入框，不包含发送操作。网页进程不持有 Docker socket，也不向公网开放 noVNC、浏览器调试或控制端口。

二维码只截取官方登录页的二维码图片；接口要求有效的同一邀请登录，图片响应不缓存。Cookie 保留在私有数据库，不送回网页。取消、过期、撤销后清除临时凭据和二维码；已提交结果会原子转入待审核配置并清除临时副本。记录清理不等于数据库磁盘块的安全擦除；备份仍应按凭据管理。

服务重启会把进行中的扫码标记为中断，用户重新开始即可，已批准配置不受影响。收到“账号不符”应使用正确账号扫码；页面结构变化或无法显示二维码时，保留手动导入方式并检查适配。查看私有数据库和调试材料时不要输出凭据。

## 原账号安全迁移

管理员直接编辑入口为 `/spark/admin?account=<网页账号ID>`，需正常密码＋TOTP 登录；没有邀请有效期限制，登录会话过期后正常登录即可。扫码、提交后返回账号管理批准新版本。当天已运行过的账号不会因此自动重新全量发送，需先核对报告再补跑明确未发送的目标。

`python -m portal.legacy_import --root /opt/douyinsparkflow` 默认只读预览。实际应用要求先停掉原发送容器及 worker，再传 `--apply --legacy-stopped`；保留 `private-migrations/` 私有备份及 `portal-data/legacy-import.json` 状态。程序只迁移单账号和当天完整报告，遇到目标不一致、未完成迁移标记等情况会停止，不猜测发送历史。按网页服务 UID 恢复私有目录属主后，重新创建 worker，使 `.env` 文件挂载指向新的占位配置。旧发送容器保持停止且关闭自动重启，不能在新 worker 启用同一账号时恢复旧任务。
