# 多账号配置网页

这是单服务器上的邀请制配置入口。原来的 `.env` 定时容器继续运行；网页接入的账号单独存储，由串行 worker 执行。原账号不会自动出现在网页中，也不要将正在运行的原账号重复接入。

## 管理员使用

1. 打开 `/spark/admin`。首次用服务器 `portal-data/admin-token` 的初始化凭据进入绑定页面，设置密码、用验证器 App 扫码，并输入当前动态码确认；保存页面只展示一次的 10 条恢复码。以后使用“密码 + 6 位动态码”登录，初始化凭据不再具有登录或重新绑定权限。
2. 创建邀请，填写便于识别的账号备注和有效期，将生成的邀请链接发给账号本人。链接持有者可以在有效期内修改这个账号的配置，因此只发给本人。
3. 本人填写并提交后，在账号列表查看待审核版本：本人抖音号、好友昵称与抖音号、消息、执行时间和通知是否配置。
4. 点击“审核并启用”批准当前版本。保存只是提交审核；启用才允许 worker 按所选时间执行。如果今天的时间已过且今天未运行过，会尽快排队执行。
5. 用户后续修改仍需审核。正在执行的配置不会被未审核修改替换。可停用账号，或撤销/重新创建邀请。停用阻止之后的新运行，不能撤回已经发送的消息或即时中断已启动的任务。

所有时间固定为北京时间。每个账号当天最多自动启动一次，失败或进程中断也不会盲目重发；修改配置、服务重启、关闭后重新启用都不会绕过当天记录。原有任务默认 09:00 运行，因此网页 worker 在 **08:30–09:10** 不启动新浏览器，并与原容器共用任务锁。网页账号选择 09:00 时会在 09:10 之后排队；其他账号或原任务未结束时还会顺延。

## 账号本人填写

1. 用邀请链接打开专属表单。链接进入后会从地址栏清除邀请凭据。
2. 输入账号备注和本人的抖音号。好友每行输入 `昵称 抖音号`；抖音号用于匹配，昵称便于核对。注意末尾的点可能属于抖音号，不要擅自删掉。
3. 在电脑浏览器打开 `https://www.douyin.com/chat` 并登录。按 F12 打开开发者工具，在 Application / 应用程序 → Storage / 存储 → Cookies → `https://www.douyin.com` 中找到 `sessionid`，复制其 **Value / 值**，粘贴到本网页的登录会话框。不要发送到公开聊天或提交到 Git。
4. 也可以粘贴浏览器导出的完整 Cookie JSON，或 `name=value; name2=value2` 格式的 Cookie。仅接受抖音域名；此处只校验格式，不保证抖音服务器仍认可该会话。单个 sessionid 若不足以登录，需要导入完整 Cookie。
5. 填写消息内容、北京时间和可选 PushPlus Token，然后提交审核。可直接输入多行消息；`[API]` 沿用项目的每日一言替换功能。
6. Cookie 和 Token 保存后不会显示原值；后续留空保留已有值。可明确清除推送配置。会话过期时重新登录，更新会话，再请管理员审核。

当前版本使用手动导入会话和填写名单。**没有接入网页内扫码、自动读取另一浏览器的登录态或自动抓取全部好友。** 普通页面不能跨域读取抖音 Cookie；不要运行来源不明的“抓 Cookie”脚本。手机可填写名单和设置，导出会话建议在本人电脑操作。

## 运行与数据位置

| 路径或服务 | 用途 |
| --- | --- |
| `/opt/douyinsparkflow` | 项目代码和部署文件 |
| `config/.env`、`logs/` | 原账号的私有配置与日志 |
| `portal-data/portal.sqlite3` | 邀请、会话、待审核及启用版本，含登录凭据 |
| `portal-data/admin-token` | 首次绑定或 SSH 恢复后的初始化凭据 |
| `account-data/runs.sqlite3` | 账号/日期幂等记录 |
| `account-data/<账号内部ID>/<日期>/` | 当次私有 `.env`、`last-run.json` 和 `runtime.log` |
| `douyin-portal.service` | 仅监听本机 18766 的网页服务 |
| `douyin-account-worker` | 网页账号串行任务容器 |
| `douyin-spark-flow` | 原账号定时容器 |

这些私有目录已加入 Git 和 Docker build 忽略。SQLite 和运行配置使用受限文件权限；这是访问权限保护，**不是数据库加密**。备份时应保护这三个私有目录；不要把数据库或环境文件放入公开仓库。

## 部署与维护

网页服务器使用 Python 标准库和 `portal/requirements.txt` 中的 qrcode（本地生成二维码）；worker 使用项目既有 Playwright 镜像。先创建 `.portal-venv` 并安装该依赖，参考 `docker/portal.service.example` 调整运行用户和域名。为网页配置 HTTPS 反向代理（例如 nginx `/spark/` 转发 `http://127.0.0.1:18766/`），设置 `PORTAL_PUBLIC_ORIGIN=https://你的域名`、`PORTAL_BASE_PATH=/spark`，代理保留 Host。不要将 18766 直接开放公网。

网页服务与 worker 必须使用同一系统 UID/GID，保证 SQLite 回滚日志也能互相恢复。Compose 默认 `1000:1000`，其他机器用 `PORTAL_UID` / `PORTAL_GID` 调整。将 `portal-data/`、`account-data/` 和既有 `logs/task.lock` 的属主设为该用户（目录 700、锁文件 600）；原 root cron 仍可使用同一锁。原配置 `config/.env` 需对该用户可读；worker 只读挂载它，用于阻止原账号重复接入。

```bash
cd /opt/douyinsparkflow
docker compose -f docker-compose.portal.yml up -d --build
sudo systemctl status douyin-portal
docker logs --tail 30 douyin-account-worker
```

首次初始化凭据可在自己的 SSH 终端查看（不要将输出贴回聊天或日志）：

```bash
ssh hz_ali 'cat /opt/douyinsparkflow/portal-data/admin-token'
```

动态码每 30 秒更新，允许前后一个时间步的时钟偏差，并拒绝重复使用已经验证过的时间步。密码保存为随机盐 + PBKDF2-HMAC-SHA256（600,000 次），恢复码只保存摘要；TOTP 共享密钥由服务器保留，受数据库文件权限保护。绑定确认前不启用 MFA；升级时旧的单凭据管理员会话失效，账号本人填写会话保留。连续失败会限流，重启不会清除限流记录。

手机暂时不可用时，登录页勾选“改用一次性恢复码”，输入密码和一条未使用的恢复码。如果忘记密码，或丢失验证器并需要重新绑定，由服务器管理员在 SSH 内执行：

```bash
sudo systemctl stop douyin-portal
cd /opt/douyinsparkflow
.portal-venv/bin/python -m portal.auth --data-dir /opt/douyinsparkflow/portal-data --reset-admin
sudo systemctl start douyin-portal
```

该命令作废原密码、验证器、恢复码和管理员会话，并生成新的初始化凭据；账号配置和任务不会删除。重新打开管理页完成绑定。没有公开网页“关闭 MFA”或“忘记密码直接重置”入口。密码和手机绑定需管理员本人操作，无需发送给维护者。

如已核对失败记录，需要手动执行当天尚未尝试的目标：

```bash
docker exec douyin-account-worker python -m account_worker --resume-account <账号内部ID>
```

补跑要求当天且已审核版本一致；已提交、提交结果不明、存在草稿或输入失败的目标不会被自动重复发送。完整成功任务不接受再次补跑。首次手动运行可用 `--run-account <账号内部ID>`，同样遵守每日幂等与旧任务保护时段。请先核对名单和登录身份，再手动执行。

正常结束时，每个账号只使用自己的 PushPlus Token 发送结果汇总。已提交仅表示按下发送键，不等同于送达/已读；停机、进程被强制终止或网络中断时不能保证推送送达。
